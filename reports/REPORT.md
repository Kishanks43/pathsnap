## Executive summary

PathSnap matches raw GPS observations to road-network arcs and reconstructs a drivable route. We trained **five models** on identical cached features (19 columns per observation-candidate pair, trusted labels only) with trip-aware 5-fold GroupKFold CV and scored all models on the untouched `student_test` partition.

- **Best CV macro F1:** random forest 0.6627 ± 0.0260.
- **Best student-test top-1:** random forest 0.8148; macro F1 0.6443; log loss 0.1307.
- **Best log loss:** random forest 0.1307 (SVM 0.1357).
- **Best inference cost:** logistic regression 0.0023 ms/obs; random forest 0.0342 ms/obs.
- **Classifier-only route continuity:** random forest 0.9031; KNN 0.9004; HGB 0.9021; SVM 0.8997; logreg 0.8915.
- **HMM/Viterbi** raises pooled student-test top-1 from 0.8148 to 0.8249 (+1.01 pp) but helps only 5 of 10 trips; it stays default with known failure cases documented.
- **Bayesian tuning** (25 Optuna TPE trials) did **not** beat the untuned forest on full-data CV/test metrics; the untuned configuration is deployed.
- **Deployment:** FastAPI on port 8000, Streamlit UI on port 8501, Docker image `pathsnap-api:local` built and smoke-tested (`/health` 200, `/predict` 200 in 1.95 s). Model weights travel outside git; git commit pins the manifest.

All figures below are generated by committed scripts from committed experiment results or raw data; no training curves were fabricated because none of the five models emits epoch-wise histories.

## 2.2 Dataset understanding and exploratory data analysis

### Which partition was used

All EDA in this section uses the **training partition** (`data/raw/train`, 80 trips). The `student_test` partition (10 trips) is reserved for final model scoring and was not used to choose features, thresholds, or model hyperparameters. The evaluator-test partition was never opened.

### 2.2.1 Data layout and preprocessing

Raw files are whitespace-separated with no header:

| File | Columns | Meaning |
|---|---|---|
| `<trip>.track` | lon, lat, timestamp | GPS fixes |
| `<trip>.nodes` | lon, lat | road-network nodes (row index = node id) |
| `<trip>.arcs` | from, to | directed road arcs (row index = arc id) |
| `<trip>.route` | arc_id | reference route (ground truth; train only) |

Preprocessing pipeline, applied identically to every model:

1. **Per-trip local projection.** Longitude/latitude are projected to metres around the trip centroid (`x = lon · cos(lat0)`, `y = lat`). A single global projection is inappropriate because trips span multiple cities/countries.
2. **Candidate generation.** For each GPS fix, candidate arcs within 100 m are found by cell-indexed bounding boxes plus exact point-to-segment distance; at most 10 candidates per fix are kept.
3. **Labels.** Each fix is assigned the reference arc from `route`; `label_residual_m` is the distance to that arc. Observations with residual ≤ 25 m are **trusted**; the rest are treated as untrusted/labels from truncated routes and are excluded from training and scoring.
4. **Features.** 19 columns per (observation, candidate) pair: distance rank/ratio, along-arc fraction, arc length, node degrees, bearings, and sequential context from the *previous observation’s nearest candidate* (not the reference arc, to avoid leakage).
5. **Missing candidates.** Observations with no candidate within 100 m are labelled “no candidate” and excluded from classifier scoring; they are counted but not imputed.

## 3.2 Per-model subsections (compulsory questions A1/A2, B5/B6, C7/C8/C9)

Every answer connects the algorithm to our actual runs, not textbook descriptions. `student_test` (10 trips) is the only partition used for C7–C9; CV figures use `train` only.

### 3.2.1 Model 1 — Logistic regression

**A1. Why suitable.** It is the cheapest interpretable baseline: one probability per candidate, fast training (3.7 s) and inference (0.0023 ms/obs). If a linear score on geometry and context cannot beat complex models, complexity is not justified.

**A2. Strengths and limitations.** Strengths: calibrated probabilities, no tuning, fast enough for real-time scoring. Limitations: linear decision boundary cannot capture nonlinear interactions (bearing change × distance × sequential context); probabilities can still hit 0 for the true class (unlike log loss we did not hit zeros here — log loss 0.1488 is finite).

**B5. Hyperparameters.** C=1.0, max_iter=2000, lbfgs, StandardScaler fitted inside each CV fold only, all 19 features, label_trust_m=25.0, GroupKFold(5) by trip, seed 42.

**B6. Loss/objective.** Binary log loss per candidate with L2 regularisation (inverse C); class imbalance handled by trusted-label filter and balanced candidate sampling, not class weights.

**C7–C9.** CV macro F1 0.6269 ± 0.0252; student-test top-1 0.7938, macro F1 0.6105, log loss 0.1488, route continuity 0.8915. Ablation: nearest-candidate baseline top-1 0.5581; geometry-only 10 features CV 0.3784 vs all-19 CV 0.6269 — context features add ~0.25 macro F1. No overfitting signal: test tracks CV within 1.6 pp and convergence warnings = 0. Underfitting signal vs the forest: RF gains +3.6 pp macro F1 and log loss drops 0.1307 vs 0.1488, so linear boundaries are too weak for this task.

### 3.2.2 Model 2 — KNN (k=11)

**A1. Why suitable.** Map matching is naturally local: the correct road is usually among the nearest candidates. KNN needs no probability model and adapts to local road density.

**A2. Strengths and limitations.** Strengths: trivial training (0.026 s), distance-weighted vote smooths ties. Limitations: inference cost grows with training size (0.5319 ms/obs with a 100k cap over 1.35M rows), `predict_proba` is a coarse k-vote, and zero-probability rows make log loss unusable.

**B5. Hyperparameters.** k=11 (selected by sweep {3,5,7,11}), weights=distance, metric=euclidean, algorithm=brute, StandardScaler inside folds, max_train_samples=100000 stratified by label, seed 42.

**B6. Loss/objective.** No training loss; prediction is distance-weighted majority vote over k neighbours. Probability estimates are vote fractions, hence coarse.

**C7–C9.** CV macro F1 0.6064 ± 0.0260; student-test top-1 0.7750, macro F1 0.5818, log loss N/A (0.5898% zero rows), route continuity 0.9004. k sweep CV: k=3 0.5601 → k=5 0.5841 → k=7 0.5949 → k=11 0.6064; small k overfits locally (noisy local vote), larger k stabilises but never catches the forest. Test top-1 0.7750 is close to CV-implied accuracy, so no severe overfit; the 100k cap causes underfitting relative to using all 1.35M rows.

### 3.2.3 Model 3 — Random forest (deployed)

**A1. Why suitable.** Handles mixed feature types, nonlinear interactions, and ranked candidate lists without probability calibration; built-in feature importance matched our feature design (rank/ratio > raw distance).

**A2. Strengths and limitations.** Strengths: best accuracy metrics, finite log loss, cheap inference relative to SVM. Limitations: 665 MiB model file, 234.8 s training, no native probability calibration beyond tree fractions.

**B5. Hyperparameters.** n_estimators=300, max_depth=20, min_samples_split=2, min_samples_leaf=2, max_features=sqrt, class_weight=balanced_subsample, random_state=42, n_jobs=-1, gini impurity.

**B6. Loss/objective.** Gini impurity minimisation per split; bootstrap aggregation across trees.

**C7–C9.** CV macro F1 0.6627 ± 0.0260; student-test top-1 0.8148, macro F1 0.6443, log loss 0.1307, route continuity 0.9031. CV-to-test drop is 1.8 pp macro F1; fold spread 0.629–0.699. The tuned forest (max_depth=10, more regularisation) scored lower on CV (0.6596) and test (0.8058/0.6344) than untuned, so we are not underfit through excess capacity; depth/leaf caps keep variance in check.

### 3.2.4 Model 4 — HistGradientBoosting

**A1. Why suitable.** Histogram-based boosting is fast on 1.35M rows (5.5 s training, 0.0136 ms/obs inference) and often matches tree ensembles on tabular features.

**A2. Strengths and limitations.** Strengths: speed, early stopping. Limitations: `predict_proba` zeros make log loss N/A (6.8e-06 zero rows); early stopping uses random rows, not whole trips, so the 85-iteration stop may be optimistic; no route-continuity recording in the original run (now added: 0.9021).

**B5. Hyperparameters.** learning_rate=0.1, max_iter=300, max_leaf_nodes=31, l2_regularization=0.0, early_stopping=True, random_state=42; iterations_used=85.

**B6. Loss/objective.** Multiclass log loss (sklearn HGB implements binary problems with the multiclass log-loss path).

**C7–C9.** CV macro F1 0.6565 ± 0.0297; student-test top-1 0.8005, macro F1 0.6368, log loss N/A, route continuity 0.9021. CV-to-test drop 2.0 pp, within fold noise (0.0297). No severe overfit; the gap to RF is 0.0062 CV macro F1, smaller than fold std, so the forest win is supported by test numbers and log loss, not a decisive CV margin.

### 3.2.5 Model 5 — RBF SVM

**A1. Why suitable.** RBF kernels capture nonlinear decision boundaries that linear models miss; Platt scaling gives probabilities.

**A2. Strengths and limitations.** Strengths: strong accuracy (top-1 0.8062, macro F1 0.6297, log loss 0.1357). Limitations: expensive (30k training-row cap, 4,533 support vectors, Platt overhead 6.69×), slow inference (1.730 ms/obs — 50× RF), superlinear scaling means the cap is binding.

**B5. Hyperparameters.** C=1.0, gamma=scale, kernel=rbf, probability=True, StandardScaler inside folds, max_train_samples=30000 stratified by label, seed 42.

**B6. Loss/objective.** Soft-margin hinge loss with C regularisation (libsvm); `probability=True` adds internal 5-fold Platt sigmoid calibration trained on held-out fold predictions.

**C7–C9.** CV macro F1 0.6431 ± 0.0271; student-test top-1 0.8062, macro F1 0.6297, log loss 0.1357, route continuity 0.8997. CV-to-test drop 1.3 pp; small cap means underfitting through data shortage is more plausible than overfitting. Platt-scaling cost measured by identical fits with probability=False vs True.

## 5 HMM and Viterbi route reconstruction

### 5.1 Hidden states
The hidden state at observation t is the **candidate road arc chosen for that observation** (one of the ≤10 candidates generated within 100 m), plus a virtual start/end. The sequence of states is the reconstructed route.

### 5.2 Emission probabilities
`log emission_t(k) = emission_weight · log(max(p_tk, 1e-6))`, where p_tk is the random-forest probability that candidate k is the correct road. The floor 1e-6 prevents an exact zero from killing a whole path (KNN can assign exactly 0 to the true road). Emissions are per-observation classifier scores; the HMM only couples them across time.

### 5.3 Transition probabilities
For consecutive states j → k:
- `d_net` = driving distance between the two positions using ≤ `max_hops` road segments.
- `d_obs` = great-circle distance between the two GPS fixes.
- `log trans = −|d_net − d_obs| / beta_m`, plus connectivity bonus +5 for connected different roads and +1 for staying on the same arc; unreachable transitions are −∞.
- Chosen settings (tuned on 10 held-out **train** trips): `beta_m=10`, `max_hops=2`.

### 5.4 Missing candidates and GPS gaps
- Missing candidates: observation emits −1 (no state); the chain continues from the previous valid state. On student_test, **zero** observations lacked candidates, so no test observation was dropped.
- Large GPS gaps (dt > 30 s or non-increasing time): chain resets; emission-only scoring resumes after the gap. `gap_resets` occur on trips 00000065 and 00000077 (1 each in the held-out set).

### 5.5 Disconnected road segments
If no valid transition exists within `max_hops` (network disconnected between fixes), that step is counted as a **forced step** and the decoder restarts from emission only; the decoded route may jump. Forced steps: HMM 3,693 vs classifier 4,196 on held-out train trips — HMM forces fewer jumps.

### 5.6 Did HMM improve the route? Yes on average, not uniformly

Held-out train trips: HMM top-1 0.8796 vs classifier 0.8743; forced steps 3,693 vs 4,196.
Student_test (10 trips), pooled: **HMM 0.8249 vs classifier 0.8148 (+1.01 pp)**; HMM better on 5 trips, worse on 5. Best trip `00000077` +7.25 pp; worst `00000009` −7.09 pp (parallel-road confusion). Route continuity 0.9638; road-set overlap (Jaccard) 0.7398; no student-test observation lacked candidates.

`figures/hmm_comparison.png` shows pooled bars and per-trip deltas; `figures/decoder_sweep.png` shows beta_m vs held-out top-1 (larger beta over-smooths). Conclusion: keep HMM decoding as default, but report worst cases (§6 map for trip 00000009) because HMM can hurt on parallel roads.
